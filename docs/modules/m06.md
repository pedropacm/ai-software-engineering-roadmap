# Módulo 06 — Agentes e workflows com estado

**Carga:** 30 horas · **Semanas:** 7, 8

## Objetivo

Construir agentes limitados, testáveis e recuperáveis após falhas.

## Escopo

- Agent loop
- React
- Plan-and-execute
- Estado
- Memória
- Retry
- Orquestração
- Multiagente
- Aprovação humana

## Ideia central

Um agente é um ciclo de decisões com ferramentas, estado e feedback. Nem todo problema exige autonomia: um workflow determinístico costuma ser mais fácil de testar. Fixe limites de etapas, custo e tempo; registre evidências e use gates humanos para operações sensíveis. Só use múltiplos agentes se houver responsabilidades e ganho mensuráveis.

## Projeto de conclusão

**Entrega:** Incident Investigation Agent com workflow e aprovação explícita.

**Critério de conclusão:** Investigação rastreável com evidências e limite de execução; nenhuma ação sensível sem aprovação.

### Comprovação mínima

1. Código, documentos ou artefato acessível no seu fork.
2. Evidência de execução (comandos e resultado) sem segredos.
3. Testes ou cenários de avaliação que outra pessoa consegue repetir.
4. Registro curto de pelo menos uma decisão técnica e uma limitação.
